# 기획 가이드

기획자 인터뷰(2026-11-21)로 정한 기준과, 레퍼런스 4개에서 뽑은 연출 패턴.
`/new-reel`은 인터뷰와 스토리보드 초안을 이 문서 기준으로 만든다.

## 1. 고정 기준

| 항목 | 기준 |
|---|---|
| 계정 표기 | `@justmade.lab` |
| 길이 | 최대 20초(엔진이 거부), 보통 12~20초 (기획자 결정 2026-11-21: 15초에서 20초로 올림) |
| 분위기 | 고정 톤 없음. 주제마다 정한다 |
| 팔레트 | 색 수 제한 없음. 주제에 맞게 |
| 문구 | 주제에 맞을 때만(기념일, 인사 등) |
| 문구 언어 | 영문만 |
| 코드 패널 | 항상 표시 |
| 상태 글자 | 항상. 1줄 계정 + 줄거리를 따라 오르는 주제별 숫자 2~4개 |
| 주제 범위 | 자연·생물, 계절·기념일, 사물·보석, 우주·추상 |
| 제작 방식 | 코드로 형체 만들기(2D 마스크, 3D 점 구름) + 실사 영상 글자 변환 |

## 2. 인터뷰 (핵심 4문항)

질문마다 **AI가 먼저 예시 3개를 제시**하고(추천 1개 표시) 기획자가 고르거나 고쳐 쓴다.
나머지 항목(훅, 오브젝트 배치, 장면 시간, 배경)은 AI가 스토리보드 초안에서 정하고 기획자가 표에서 고친다.

1. **컨셉과 클라이맥스**: 무엇이 어떻게 완성되고, 이 영상의 질문(보는 사람이 끝까지 궁금해하는 것)에 어떻게 답하는가
   - 예시 3개는 서로 **다른 클라이맥스 유형**(6번 목록)으로 낸다. 모두 폭발형으로 내지 않는다.
   - 예(해파리): 질문 "저 빛은 무엇이 될까?" / 완성·공개형: 촉수까지 다 자란 해파리가 첫 박동으로 헤엄쳐 나감
2. **분위기와 색**: 배경 톤, 주색, 강조색, 색 전환을 넣을지
   - 예: 심해 남색 배경 + 형광 파랑, 전환 후 분홍·청록
3. **문구**: 넣을지, 넣는다면 영문 문구와 등장 시점
   - 예: 없음 / `MERRY CHRISTMAS 2026` 9.4초부터 타이핑
4. **상태 숫자**: 줄거리를 따라 오를 숫자 2~4개
   - 예: `beats`, `tentacles`, `colours`, `letters`

## 3. 연출 패턴 목록 (장면표를 짤 때 고른다)

| 패턴 | 설명 | 레퍼런스 | 엔진 기능 |
|---|---|---|---|
| 아래에서 자라기 | 형체가 바닥부터 위로 드러남, 끝선이 반짝 | 트리 | 2D 마스크 + `smooth` |
| 불씨 모이기 | 흩어진 `+ *`가 모여 윤곽이 됨 | 해파리 | 점 위치를 시간으로 보간 |

| 색 물결 | 흰 띠가 몸을 타고 흐르며 팔레트 교체 | 해파리 | 해파리 시안 `colour_wave` |
| 회전 공개 | 천천히 돌며 입체감, 앞뒤 가림 | 트리, 반지 | `rot_y`, `splat` |

| 바닥 원근 | 멀수록 작고 촘촘, 가까울수록 크고 드묾 | 밤 꽃밭 | `ground`, `sprites` |
| 카메라 무빙 | 클로즈업에서 빼며 공개, 주인공 쪽으로 밀어 들어가기(push-in), 위로 틸트, 충격 때 흔들림, 천천히 다가가기 | 소환 의식 | `camera`, `orbit` |
| 페이드 루프 | 끝에서 배경만 남겨 첫 화면과 같게 | 전부 | `ease` |

## 4. 실사 영상 소스 규칙

- 직접 찍은 영상, 직접 만든 영상, 이용 허락이 분명한 소스만 쓴다. 출처를 스토리보드 기본 항목에 적는다.
- 어두운 배경에 피사체가 밝은 영상이 잘 나온다(어두운 칸은 비워진다).
- 원본은 `sources/`에 두고, 영상 길이보다 길면 쓸 구간을 스토리보드에 적는다.

## 5. 갤러리 복사용 프롬프트 작성 규칙

목표: 저장소를 모르는 다른 에이전트(Claude Code, Codex)가 프롬프트만 보고 **비슷한 결과**를 내는 것.
2026-11-21 재현 시험 두 번(에이전트 2개씩)에서 실제로 해석이 갈린 지점을 규칙으로 만들었다.

1. **값은 한 곳에만 쓴다.** 공통 프롬프트(`_base`)의 기본값과 주제 프롬프트 값이 다르면 주제 쪽에 "기본값 대신 이것"이라고 적는다. 같은 것(예: 주광 방향)을 두 군데 다르게 쓰지 않는다.
2. **단위와 좌표계를 적는다.** 모델 단위인지 화면 단위인지, `scale`·`cy`를 곱하기 전인지 후인지. 회전·기울기가 어느 물체에 적용되고 어느 물체에는 안 되는지.
3. **공식 속 낱말을 다 정의한다.** "역광 정도", "빛을 향한 정도", "그림자" 같은 말은 식으로 바꾼다.
4. **물체를 이루는 점이 어디서 오는지 적는다.** 예: "행성 = 내려앉은 먼지 그 자체, 점 추가 없음". 개수, 분포(균등/정규), 구간(C·B·A 고리 반지름)을 숫자로.
5. **숫자(상태 글자)를 어떻게 세는지 식으로 적는다.** 예: `dust = int(4812 * mean(k))`.
6. **보기 좋게 바꾸고 싶어질 곳은 미리 막는다.** 원본과 다르게 손댈 만한 부분(초승달 모양, 번쩍임 세기)은 "바꾸지 않는다"와 그 이유를 적는다.
7. **의도된 어긋남은 미리 말한다.** 예: "시작할 때 바깥 먼지가 화면을 살짝 넘는데 그대로 둔다". 안 적으면 에이전트가 자체 점검에서 '오류'로 보고 고친다.
8. **시간 압축과 반복 규칙은 공통 프롬프트를 따른다.** 길이를 바꾸면 시간 x 배율, 속도 x 역수. 반복 이음새는 렌더 화면만.
9. **장면표를 위에, 정확한 값을 아래에.** 사람은 장면표로 이해하고, 에이전트는 아래 값으로 만든다.
11. **숨기는 방법과 시간 압축 대상을 적는다.** 아직 안 보여야 하는 것은 "밝기 0.02 이하는 그리지 않는다"로 숨긴다고 적고,
    길이를 바꿀 때 무엇이 시간이고 무엇이 속도이고 무엇이 그냥 각도인지 나눠 적는다(2차 시험에서 가장 많이 갈린 부분).
10. **값은 실제 주제 스크립트에서 옮긴다.** 기억으로 쓰지 않는다. 스크립트를 바꾸면 프롬프트도 같이 바꾼다.

### 재현 시험 (등록 전 권장)

새 프롬프트는 갤러리에 올리기 전에 저장소를 보지 못하게 한 에이전트 2개에게 같은 프롬프트로 3초 버전을 만들게 하고,
원본과 같은 시점(원본 시간 x 0.2) 정지 화면을 나란히 비교한다. 두 에이전트가 "추측했다"고 보고한 항목을 1~10 규칙에 맞춰 프롬프트에 반영한다.

## 6. 클라이맥스 설계

기획자 결정(2026-11-21): 클라이맥스를 억지로 과장하지 않는다. 스토리에 맞는 유형을 고른다.

- **정의**: 클라이맥스는 "가장 큰 폭발"이 아니라 **영상 초반에 생긴 질문에 답하는 순간**이다.
  스토리보드에 `이 영상의 질문`과 `클라이맥스가 답하는 방식`을 한 줄씩 적는다.
- **강도의 기준은 대비**다. 밝기·입자 수가 아니라 앞 장면과 무엇이 달라지는가(크기, 속도, 색, 정적 -> 움직임, 움직임 -> 정적).
  고요한 클라이맥스도 앞을 충분히 채워 두면 강하다.
- **복선**: 클라이맥스에 쓰는 요소(색, 형태, 움직임)는 앞 장면에 작게라도 먼저 보여 준다. 처음 보는 것이 갑자기 터지면 뜬금없다
  (오로라 1차안의 아치형 코로나가 그 예).
- **하나만**: 클라이맥스 유형은 하나를 고르고, 다른 유형의 이펙트를 덧붙여 과장하지 않는다(폭발형에 문구, 섬광, 흔들림을 다 얹지 않기).

| 유형 | 답하는 방식 | 어울리는 주제 | 예 |
|---|---|---|---|
| 완성·공개형 | 마지막 조각이 맞춰지며 전체가 드러남 | 조립, 성장, 그리기 | 토성 고리가 다 퍼짐, 시계 톱니가 맞물림 |
| 변환형 | 쌓인 것이 다른 존재로 바뀜 | 탈바꿈, 진화 | 잉어가 용이 됨, 봉오리가 꽃이 됨 |
| 폭발·해방형 | 모인 힘이 한 번에 풀려남 | 의식, 축제, 자연재해 | 불꽃놀이, 화산 분화 |
| 고조·절정형 | 같은 움직임이 점점 커져 정점에 이름 | 날씨, 빛, 춤 | 오로라 서브스톰, 번개 폭풍 |
| 고요·여운형 | 움직임이 멈추고 완성된 장면이 조용히 빛남 | 풍경, 명상, 밤 | 눈 내린 숲에 마지막 별 하나가 켜짐 |
| 반전형 | 보던 것의 정체나 크기가 드러남 | 미스터리, 스케일 | 작은 빛인 줄 알았는데 거대한 고래의 눈 |
| 귀환·순환형 | 처음 장면으로 돌아오지만 달라져 있음 | 계절, 생명 주기 | 벚꽃이 지고 같은 가지에 새싹 |
