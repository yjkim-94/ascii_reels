# new-reel

입력: 주제(필수). 분위기, 색, 문구는 있으면 쓰고 없으면 기본값을 제안한다.
계정 표기는 항상 `HANDLE = "@justmade.lab"`.

## 0. 인터뷰 (핵심 4문항)

`storyboards/GUIDE.md`의 고정 기준을 먼저 읽는다. 기준에 이미 정해진 것(계정, 길이, 코드 패널, 문구 언어)은 묻지 않는다.
AskUserQuestion으로 4문항(컨셉·클라이맥스, 분위기·색, 문구, 상태 숫자)을 한 번에 묻는다.
질문마다 **주제에 맞춘 구체적인 예시 3개를 먼저 제시**하고 하나에 "(추천)"을 붙인다. 기획자는 고르거나 직접 쓴다.
실사 영상을 쓸 주제면 소스 파일과 출처도 묻는다.

## 1. 스토리보드 (사람 승인 1)

1. 인터뷰 답을 바탕으로 `storyboards/_template.md`를 복사해 `storyboards/<slug>.md` 초안을 채운다.
   예시는 `storyboards/saturn.md`. 장면표의 연출은 `GUIDE.md` 3번 연출 패턴 목록에서 고른다.
2. 지킬 것
   - 길이 20초 이하. 첫 1초 안에 움직임(훅). 형체 완성은 55~70% 지점.
   - 클라이맥스는 하나, 앞 장면보다 확실히 강하게(색 전환, 빛 터짐, 문구 등).
   - 끝 1.5초는 페이드 등으로 첫 화면과 같게(반복 재생).
   - 오브젝트는 Y 0.85 위에 둔다(아래는 HUD 자리). 자막은 Y 0.80~0.86.
   - 형체는 표현 방식을 고른다. 회전하거나 앞뒤가 가려지는 것은 3D 점 구름(`splat`),
     평면 실루엣은 2D 마스크(`g.put`), 가는 선은 방향 글자(`dir_chars`).
   - 실사 영상을 쓰면 `Footage`로 읽고 `draw_footage`로 그린다. 드러남·색 전환 같은 연출은 마스크와 색으로 얹는다.
   - 하늘·바다·들판 같은 풍경은 그림 층(`under`: 그라데이션, `noise2d` 구름)을 깔고 글자를 포인트로 얹는다. 바닥 위 물체는 `ground`로 원근을 주고 `sprites`로 멀수록 작게 찍는다.
   - 광택 있는 물체는 `light`(주광, 테두리광, 반짝임)로 음영을 주고, 받침이 있으면 `splat_reflection`으로 바닥 반사를 넣는다.
3. 스토리보드 표를 사용자에게 보여 주고 **승인을 받은 뒤** 코드로 넘어간다. 바꿀 점을 받으면 표를 고친다.

## 2. 주제 스크립트

`themes/<slug>.py`. 규약은 `README.md` "주제 스크립트 규약". 참고 구현은
`themes/saturn.py`(3D 점 구름, 조명, z-buffer). 그 밖의 기능은 `README.md` 규약을 본다.

- 필수 상수: `TITLE`, `DURATION`(<=20), `SCENES = [(이름, 시작, 끝), ...]`(스토리보드 장면표와 같게), `POSTER_T`(썸네일 시각, 보통 클라이맥스 직후).
- 시간 구간은 `T_*` 상수로 맨 위에 모은다. 화면에 코드가 나오므로 이 부분이 "타임라인"으로 읽혀야 한다.
- `draw(g, t)`는 t만으로 결정한다. 난수는 모듈 로드 때 고정 시드로 미리 뽑는다.
- 주석과 문자열은 영어/ASCII만(코드 글꼴에 한글이 없다). 한 줄 72자 이하.
- 밝기 합성 규칙: 칸에는 더 밝은 글자만 덮어쓴다. 어두운 글자로 가리기는 안 된다.
- 3D 좌표는 x, y 같은 단위(화면 폭 절반 = 1)다. `splat`의 `cy`, `scale`로 위치와 크기를 맞춘다.

## 3. 자동 점검과 자체 검토

```bash
python check.py themes/<slug>.py
```

- FAIL은 모두 고친다. WARN은 이유가 있으면 남겨도 된다(예: 페이드 구간 정지).
- `out/<slug>_check.png`를 Read로 직접 보고 스토리보드와 대조한다.
  흔한 문제: 오브젝트가 화면 밖으로 잘림, HUD·자막과 겹침, 너무 어두움, 장면 사이 변화가 없음,
  시작 전 커서나 잔상이 보임, 페이드 뒤 검은 구멍.
- 고치고 다시 점검한다. 3번 돌아도 안 풀리면 멈추고 무엇이 걸리는지 사용자에게 말한다.

## 4. 사람 검수 (사람 승인 2)

점검 시트와 미리보기(`python render.py themes/<slug>.py`, 약 1분)를 사용자에게 보낸다.
스토리보드 6번 체크리스트(분위기, 클라이맥스 강도)는 사람이 판단한다. 내가 통과라고 단정하지 않는다.

## 5. 갤러리 등록

승인을 받으면:

```bash
python publish.py themes/<slug>.py
```

`gallery/manifest.json`에 항목이 생긴다. 이어서 웹 갤러리용으로:

- `gallery/cards.json`에 제목과 한 줄 설명(ko, en)을 넣는다(맨 앞에 넣으면 갤러리 맨 앞).
- `gallery/prompts/<slug>.ko.md`, `<slug>.en.md`에 복사용 프롬프트를 쓴다. **`storyboards/GUIDE.md` 5번 작성 규칙을 반드시 따른다**
  (장면표 + 주제 스크립트에서 옮긴 정확한 값, 단위·좌표계, 공식 속 낱말 정의, 숫자 세는 식, 의도된 어긋남). 계정 자리는 `@your.handle`.
- 재현 시험을 권한다: 저장소를 못 보게 한 에이전트 2개에게 3초 버전을 만들게 하고 원본과 비교해, 추측했다고 보고한 항목을 프롬프트에 반영한다.
- `node web/build.mjs`로 빌드가 되는지 확인한다.

스토리보드, 주제 스크립트, manifest, cards, prompts를 커밋하고 push하면 Vercel이 자동 배포한다.
